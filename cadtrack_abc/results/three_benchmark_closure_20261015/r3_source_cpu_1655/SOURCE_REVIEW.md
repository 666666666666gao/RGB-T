B's first horizon element predicts the current query frame, using `current_frame - last_accepted_frame`; subsequent elements add one and two frames (`cadtrack_abc/dense_temporal.py:31`, `:44`). `labels[:, time:time+3]` therefore aligns with the forecast (`cadtrack_abc/dense_main_model.py:182`). 3. **The motion likelihood and grid have distinct, consistent roles.** The trajectory objective sums masked per-step four-dimensional Gaussian log densities within each mode, adds a mode log weight once, then uses log-sum-exp over modes (`cadtrack_abc/dense_temporal.py:89`). Candidate evidence reuses the corresponding single-step mixture log probability (`cadtrack_abc/ported_modules.py:61`; `cadtrack_abc/dense_submission.py:32`). Mode weights are log-softmax normalized. Deviations have a positive floor, a capped base scale, and a square-root time-gap multiplier (`cadtrack_abc/dense_temporal.py:47`). The grid is a weighted, unnormalized two-dimensional Gaussian bump per mode, followed by two expected log-size channels, trust, and log gap (`:73`, `:77`, `:83`). It is not a normalized crop-conditional density and should not be reported as one; avoiding crop renormalization is an explicit choice at `:79`. The grid uses the same center/half-side coordinate convention as dense candidates (`cadtrack_abc/dense_model.py:38`). Multi-mode usefulness, calibration, and recovery after long deferrals remain empirical questions.

4. **Trainable gradients have intended source paths.** The ViT extractor runs under no-grad, while A, fusion, the motion residual, and the Center head execute outside that wrapper (`cadtrack_abc/dense_model.py:132`; `cadtrack_abc/dense_main_model.py:70`). Real finite/nonzero group gradients and parameter changes still need measurement; weight-change counts alone are not proof of useful learning.
